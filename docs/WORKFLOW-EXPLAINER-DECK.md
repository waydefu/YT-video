# 科普／教學 PPT 的完整製作工作流（依 Anatomy 簡報實作更新）

> 版本 2026-11-06。這是 `QUALITY-GATED-WORKFLOW.md`（G0–G5）在「**正式簡報 + 無縫 Morph 轉場 + 官方素材**」這類交付物上的具體做法。內容來自實作 [`ANATOMY-EXPLAINER.md`](ANATOMY-EXPLAINER.md) 的過程，包含踩過的坑。**本文件不是任何作品通過驗收的證據。**

## 0. 一圖看全流程

```text
P0 契約與誤讀檢查 ──► P1 主題與事實台帳 ──► P2 官方素材管線 ──► P3 分鏡（頁面×轉場×素材）
        ▲                                                          │
        │                                                          ▼
P9 交付（PR・不合併）◄── P8 C/D 層：PowerPoint 實播・匯出・手機 ◄── P4 最小樣片（G2）
                                   ▲                                │
                                   └── P7 B 層（逐頁＋轉場代理）◄── P6 A 層 ◄── P5 建置（G4）
```

每一步都要回答：**這步證明了什麼，沒證明什麼。** A（結構）、B（靜態與代理）、C（原生實播）、D（裝置）、E（內容與授權）互不取代。

## P0. 契約與誤讀檢查（G0）

1. 用**一句話**重述交付物，並寫出「**它不是什麼**」。例：「正式、可編輯的 PPT，轉場是原生 Morph 的無縫鏡頭運動；**不是**角色動畫、**不是** MP4。」
2. 使用者用語有歧義時（例如「Live 2D」），**先列出兩種合理解讀與各自的後果**，在第一則回覆就說明採用哪一種；差異大且無法自行判斷時才提問，一次問清。
3. 把決定寫進文件（交付契約表），後續不得悄悄改媒介、比例、素材來源。
4. **教訓**：本實作曾把「轉場更帥」誤讀成「活的 2D 角色」，花了一整輪才更正。**重述→確認**比事後重做便宜。

## P1. 主題與事實台帳（G1）

1. **找一手來源**：產品／技能類主題以官方 repo 或文件為準，**固定到 commit 或版本**，記錄核對日期。
2. 建事實台帳：每個陳述對應來源章節；標示證據等級（**A** 官方／作者原文、**B** 具名轉述、**C** 我的推導）。
3. **誠實界線**：沒有實際安裝或執行過，就不能寫「實測」；只能寫「官方文件說」。推導出的段落（例如適合誰／不適合誰）在畫面上標註「依官方定位整理」。
4. 數字與限制逐字對照來源，不憑印象補全；需要人工核對的事實，在交付時列成清單。

## P2. 官方素材管線（G1）

模板：`scripts/anatomy_assets.py`（可複用到其他上游專案）。

| 步驟 | 規則 |
| --- | --- |
| 固定來源 | 固定 commit；每個輸入檔記錄 **SHA256**；不符即停止，**不替代、不降級成佔位圖** |
| 取素材 | 優先順序：官方向量／原檔 → 官方頁面截圖 → README 縮圖。向量 PDF 以 300 dpi 光柵化；用**墨跡範圍自動裁切**，不要手填座標（手填曾切掉零件） |
| 擷取官方頁面 | 無頭瀏覽器以 2–3× 擷取**圖卡元素**，**不修改頁面**；需要互動狀態（如拆解）就用官方 README 圖 |
| 授權 | 保留授權全文：每頁講者備註 + 畫面可見署名 + CI 產物附授權與 `manifest.json` |
| 不入庫 | 素材輸出放 `build/`（已 gitignore），repo 只放腳本與雜湊；改用官方素材要先更新 `docs/ASSET-RIGHTS.md` |
| 不改作 | 機械式取景可以；重繪、補畫、AI 生成「像官方」的圖不行 |

## P3. 分鏡：頁面 × 轉場 × 素材（G1→G2）

先寫一張表：**頁碼｜這頁只傳達一件事｜轉場手法｜用哪張官方圖｜事實來源**。

**轉場手法與規則**（`scripts/pptx_world.py`；以下縮放比與限制是**設計假設，需 C 層實播驗證**）：

| 手法 | 做法 | 規則 |
| --- | --- | --- |
| 平移 | 下一頁在旁邊／下方，同縮放 | 頁間留縫隙；縫隙顯示底色，視為牆面 |
| 鑽進視窗（zoom-through） | 下一頁是上一頁預留的「視窗」裡的縮圖 | 視窗寬度固定（本實作 3.9 英吋），單段縮放比約 3.4×（建議 ≤ 3.5×，超過就拆段） |
| 拉遠揭露（pull-back） | 上一頁原來是更大場景牆上的畫框 | **畫框寬＝視窗寬**，縮放回 1；大場景只存在於它自己那頁以後（Morph 淡入） |

- **鑽進視窗之後必須接拉遠揭露**；直接接平移會落在父頁裡面。三連（視窗→畫框）＋平移是可重複的節奏。
- 每頁一個重點；密集頁要先問「能不能拆頁」。
- 字級預算（影片）：標題 ≥ 40 pt；內文建議 ≥ 24 pt；**16–20 pt 是風險**（手機偏小），用到就要在報告中列為缺陷。驗證器最低門檻 14 pt。
- 邊緣安全區 5%；文字寬度估算：全形字約 1 em 寬，先算每行字數再決定字級。
- 單一形狀 ≤ 約 55 英吋（放大後的底圖要切塊，接縫放在任何鏡頭都看不到的位置）。
- 目標頁才有的物件會淡入；**淡入過程中舊頁可能暫時透出**，要在 B 層代理幀確認不礙眼。

## P4. 最小樣片（G2）

**先做 3–4 頁**，涵蓋三種手法，不加內容。`build_science_explainer.py` 是這種樣片的範例。通過 A + B（含轉場代理）才擴到完整頁數；C 層無法執行時標記 BLOCKED，仍可擴充**技術內容**，但狀態只能是 SPIKE/PREVIEW/CANDIDATE。

## P5. 建置（G4）

```bash
python3 scripts/anatomy_assets.py                       # 官方素材（需 poppler-utils、Node + playwright）
python3 scripts/build_anatomy_explainer.py \
  --hold 8000 --duration 1500 \
  --font-sans "…" --font-serif "…" --font-mono "…"      # 字型必須已安裝在播放電腦
```

- 每頁像一般 13.33×7.5 英吋投影片設計（面板座標）；擺位、可見面板、文字補償由 `pptx_world.py` 處理。
- 所有會 Morph 的物件使用全域唯一的 `!!` 名稱（`!!P03_title`…）。
- `--hold` 依**旁白長度**設定；預設 8 秒只是展示。
- **字型**：指定的字型必須在播放（或錄影）的電腦上存在；本專案不隨附字型檔。
- **陰影**：python-pptx 的自動圖形預設引用主題陰影，建置時一律加空的 `a:effectLst`。

## P6. A 層：結構（本地與 CI）

```bash
python3 -m unittest discover -s tests -v
python3 scripts/pptx_validate.py DECK.pptx --min-loops 0 --strict --readable DECK.readable.json
```

- `--readable` 只檢查「該頁要讀的文字」（字級、安全區）；縮小嵌入的視窗文字不算。
- 驗證器證明：XML 順序、ID 唯一、跨頁 `!!` 錨點、Morph＋備援；**不證明**轉場順不順。

## P7. B 層：逐頁與轉場代理

1. LibreOffice 轉 PDF／PNG，**每一頁都看**（不是抽樣）；檢查文字溢出、被框線或圖壓住、右緣與下緣、字被裁、圖是否清楚。渲染用的是替代字型，Latin 與換行會略有差異。
2. `pptx_morph_proxy.py` 產生每段轉場的中間幀（逐物件線性插值），**每一段都看**：有無空洞、閃現、物件穿過文字、縮放比例是否過猛。**代理只能否決設計，不能證明實播。**
3. 修正 → 重建 → 再看，直到自己找不出明顯缺陷；**主動列出三個最可能降低品質的缺陷**（沒有也要附檢查依據）。
4. 不要把 B 層結果寫成「轉場很順」。

## P8. C/D 層：Microsoft PowerPoint 實播、匯出、手機

此層需要使用者或有 PowerPoint 的環境。給使用者的檢查單：

- [ ] 開檔**沒有修復提示**
- [ ] 投影片放映：12 段轉場都是連續的鏡頭運動，沒有跳位、閃現、文字突然換大小
- [ ] 每頁停留時間符合旁白
- [ ] 字型正確（排版沒有跑掉）
- [ ] 匯出 1080p 影片（建議先小段試匯出）：Morph 是否保留、有無掉格；`ffmpeg -vf freezedetect` 檢查凍結段
- [ ] 手機尺寸看一次：內文是否讀得清楚
- [ ] 低階電腦放映是否卡頓（每頁 40–140 個物件）

結果回報後才可能升級狀態；**沒有證據就維持 BLOCKED / NOT RUN。**

## P9. 交付

1. 從**最新 main** 開／重設分支（已合併過的分支不重用：`git fetch origin main && git checkout -B <branch> origin/main`）。
2. 提交訊息與 PR 說明要有：需求對照、最小樣片證據、A/B/C/D/E 分層狀態、三個缺陷、未驗證項目、需使用者核准的事項（見 `.github/PULL_REQUEST_TEMPLATE.md`）。
3. PR 先開 **draft**；訂閱 PR 事件；CI 紅就修，**不跳過測試**；**不自動合併、不替使用者發布**。
4. 合併後不重開同一個 PR；後續修改走新分支。
5. 簡報成品（pptx）與素材在 `build/`，不進 git；用 CI 產物或直接傳檔給使用者。

## 常見狀況速查

| 狀況 | 做法 |
| --- | --- |
| 需求措辭有歧義 | P0：列兩種解讀、說明採用哪種、必要時問一次 |
| 官方圖解析度不夠 | 找官方向量來源（A4 PDF）或頁面擷取；不要放大糊圖；不夠就縮小使用比例 |
| 想用的圖沒有授權說明 | 不用；記錄在 `ASSET-RIGHTS.md` 的「不可用」 |
| 密集頁在手機太小 | 拆頁（先報告再做）或放大；不要偷偷縮字 |
| 轉場代理看起來怪 | 先懷疑設計（縮放比、z 順序、淡入）；不要假設實播會自動變好 |
| CI 全綠 | 只代表 A 與 B 的自動化部分通過；不是畫質或動畫通過 |
| 沒有 PowerPoint | C/D 標 BLOCKED／NOT RUN；把檢查單交給使用者 |

## 實作中踩到的坑（已寫進工具）

| 問題 | 原因 | 現在的處理 |
| --- | --- | --- |
| 誤讀需求 | 「Live 2D」被當成角色動畫 | P0 誤讀檢查 |
| 鑽進視窗後的平移目標落在父頁內 | 下一頁與父頁座標重疊 | 規則：鑽進視窗後必接拉遠揭露 |
| 連續拉遠後越縮越小 | 畫框寬度與視窗寬度不同 | 畫框寬＝視窗寬 |
| 單頁出現超大形狀 | 父頁被放大 ≥ 56 英吋 | `pptx_world.py` 超過 55 英吋就報錯；只畫相鄰鏡頭可見的面板 |
| 廣角畫面出現一條細縫 | 大背景切塊的接縫落在畫面內 | 接縫放到任何鏡頭看不到的位置 |
| 驗證器對縮圖文字誤報 | 縮小的視窗文字被當成正文 | `--readable` 清單 |
| 圖形帶出主題陰影 | python-pptx 預設引用主題效果 | 一律加空 `a:effectLst` |
| 官方海報裁切切掉零件 | 手填裁切座標 | 墨跡範圍自動裁切 |
| 轉場插入位置錯誤 | transition 必須在 clrMapOvr 後、timing 前 | `pptx_morph_patch.insert_transition` |
| 字型在別台電腦不同 | 指定字型未安裝 | 字型參數 + 文件警告；不隨附字型檔 |
