# 品質優先的交付工作流（Quality-Gated Production Workflow）

> **適用範圍：本 repo 的所有影像、影片、動態簡報、互動展示、Blender 場景、UI 與相關製作程式。**
> 本文件規範工作方式；它**不是**任何作品已通過品質驗收的證據。版本：2026-11-06。
> 簡報（正式 PPT + 無縫 Morph 轉場 + 官方素材）的逐步做法見 [`WORKFLOW-EXPLAINER-DECK.md`](WORKFLOW-EXPLAINER-DECK.md)。

## 最高原則：先證明品質，再擴大製作

**「程式可執行／檔案已產生／PR 已開／CI 綠」只證明特定技術環節成立，不代表成品體驗達標。**

使用者指定的媒介、原生動畫、參考影片、版面和畫面品質屬**交付契約**。不能擅自把「Canva 原生轉場」改成「靜態 Canva 簡報」，不能把「PowerPoint 原生 Morph」改成「外部 MP4 嵌在 PPT」，也不能拿以程式渲染的影片冒稱已驗證 PowerPoint 動畫。

**不能實際檢視、播放或操作時，必須顯示「未驗證／受阻」，絕對不可寫成完成或推論達標。** 開 PR 是提供程式與證據供審查，不是宣布作品完成。

## 工作流程：先最小樣片，通過後再擴大

```text
G0 釐清交付契約與參考基準
    ↓
G1 素材與視覺方向（查證來源／授權）
    ↓
G2 最小可驗證樣片（先做最難的關鍵效果）
    ↓
G3 自行實際驗收（功能＋畫面＋播放＋裝置）
    ├─ FAIL → 改方向／重做 G1–G2，不以補丁掩飾根因
    ├─ BLOCKED → 停在「未驗證」，誠實回報環境限制
    └─ PASS → G4 完整製作，逐段重跑 G3
                  ↓
G5 交付／PR／使用者驗收（不自動合併或發布）
```

### G0 — 確定交付契約

- 寫清楚**真正交付物**：原生 Canva 設計／PPTX＋Morph／Blender .blend／MP4／網站／互動遊戲。
- 列出不可妥協條件：真實轉場、視覺等級、16:9、安全區、字幕、語言、輸出格式、手機體驗、素材合法性等。
- 使用者給的參考影片屬**品質門檻**，不是可直接複製／再散布的素材。
- 避免沒有必要的詢問；只有關鍵媒介或權限尚不清楚時才詢問。媒介已明確時不擅自更換。
- **誤讀檢查**：用一句話重述交付物並寫出「它不是什麼」；措辭有歧義（例如「Live 2D」可能是角色動畫，也可能只是「像動畫一樣流暢的轉場」）時，列出兩種解讀與後果，在第一則回覆說明採用哪一種，差異大且無法自行判斷才提問一次。更正契約比事後重做便宜。

### G1 — 來源／視覺／架構先行

- 搜尋可信的**官方、原作者或合法授權**圖片、模型、示範片、音效；記錄來源、授權、取得日、商用限制。禁止默默下載／內嵌未知授權內容。
- 先建立視覺方向樣張／畫面構圖草圖；比較清晰度、質感、色彩、主次、中文字級、前後鏡頭錨點。
- 先判斷工具**能否完成最難的原生功能**。Canva 連接器若無法寫入動畫，不得因為能建立頁面就宣稱可交付原生轉場；需要時轉向使用者明確授權的 PPTX 程式路線。
- 禁止在缺乏依據時誇大「電影級、世界級、絲滑、高品質」等結論。

### G2 — 最小可驗證樣片（MVP／Spike）

- 對電影式簡報：先製作 **10–15 秒、2–4 個連續鏡頭** 的**原生**轉場；須包含實際關鍵效果（特寫→拉遠揭露→平移）。
- 對 Blender：優先至少一個最難鏡頭（燈光、煙霧、鏡頭、主體、物理／非物理效果有清楚區別）；先 smoke 再 preview。
- 對互動網站／遊戲：先打開最關鍵的互動路徑，確認輸入、動作、狀態和畫面可用；單純 build success 不夠。
- **暫不擴增頁數、視覺裝飾、轉場類型或全套內容**，直到關鍵鏡頭通過 G3。
- 保留可修改的原稿／source 與明確檔名（`spike`、`preview`、`candidate`、`final-approved`）。

### G3 — 由製作者先實際驗收

分開紀錄證據，**各層不能互相代替**：

| 驗收層 | 必須確認 | 不能據此推論 |
| --- | --- | --- |
| A. 原始檔與結構 | PPTX XML / Morph、音視訊編碼、模型／網站能載入、CI／單元測試 | 「動畫順暢」「畫面好看」 |
| B. 靜態視覺 | 代表畫格／每頁全幅、繁中字體、層次、對比、文字遮擋、安全邊、裁切 | 「播放轉場已驗證」 |
| C. 動態實播／互動 | 在**目標播放器／目標瀏覽器**看全段或實際操作，檢查跳幀、錯配、連續性、遮擋、節奏、音畫同步 | 不可拿其他軟體的靜態渲染代替 PowerPoint Morph 實播 |
| D. 裝置與觀眾 | 桌面與手機檢查可讀性／點擊、重看高潮與過渡段、按原參考標準比較 | 僅因解析度正確就視為合格 |
| E. 內容與權利 | 安裝指令、功能限制、註腳、授權、商用條款、引用來源；不得編造成功實測 | 一張效果圖就是作者真實輸出 |

**簡報的補充（B 層）**：除逐頁靜態檢視外，每一段 Morph 轉場要看逐物件插值的中間幀（`scripts/pptx_morph_proxy.py`）；代理**只能否決設計，不能證明實播**。字型與播放器版本屬 C／D 的前置條件，要在報告中寫明是否已知。

具體作業：
1. 自己先看，並主動**指出三個最可能降低品質的缺陷**（若確實沒有也應附檢查依據）。
2. 若明顯不達使用者參考基準，標記 **FAIL**，不要推給使用者當第一位測試者。
3. 若**欠缺 Microsoft PowerPoint** 或特定 Canva 功能，標記 **BLOCKED / NOT RUN**；檔案可以交為技術候選，但**不能**宣稱動畫驗收合格。
4. 發現本質上「視覺方向不對」，回 G1 **更換素材與構圖**，而非繼續局部調字體、堆更多特效。
5. 合格與否以**指定的實際體驗**為準，不能靠主觀評分或文件自我宣告。

### G4 — 擴展完整作品，持續把關

- 一般情況：G3 PASS 才擴展到長影片／完整頁數／多場景。
- **例外（使用者明確要求完整內容，且 C 層因環境無法執行）**：可在 A 層與 B 層（含轉場代理）通過後擴充**內容**，但狀態只能是 SPIKE／PREVIEW／CANDIDATE，報告必須列出 C／D 未驗證，且**不得宣稱完成**。
- 分批製作：每新增一組鏡頭／場景就檢查前後連續性與媒介的原生行為；不把風險留到最後。
- 用真正取得的來源與合法素材；若只是美術概念示意，清楚標示而不偽裝成工具實際產出。
- 改動功能與動效都要回歸測試；不能因已有成功測試就跳過新版本的驗收。

### G5 — 交付與 PR

- **必須**附：原稿／原生格式、預覽或足夠的視覺證據、測試命令與結果、尚未驗證項目、問題清單、素材權利狀態。
- 清楚標明：`RESEARCH`／`SPIKE`／`PREVIEW`／`CANDIDATE`／`FINAL-APPROVED`，不得用 `final` 命名未經使用者核准之作品。
- PR 說明要有「需求對照＋最小樣片證據＋實播驗收狀態＋未解決風險」。保留審查權，不自動合併、不替使用者發布。
- 只有全部必需 Gate PASS 且使用者完成必要驗收，才可稱「正式成品已完成」。

## 針對本專案的不可變規範

- **Canva**：原生動畫必須實際出現在 Canva 編輯器／播放器；靜態 Canva 頁面 + 另製影片只能標為旁路原型，**不是** Canva 原生轉場成品。
- **PowerPoint**：`p159:morph` / 匹配物件 XML 是 A 層證據；必須在支援 Morph 的 Microsoft PowerPoint 實播，才能通過 C 層。LibreOffice／轉成 PDF 只可用於 B 層。
- **Blender**：程序化 2D 拼貼不可稱真 3D；程序碎片路徑不可稱剛體物理模擬。以真實 rendered frame 與片段為依據。
- **YT-video**：遵循 `AGENTS.md`、`docs/SHOTLIST.md`、`config/production.json`、`docs/ASSET-RIGHTS.md`；畫面 1920×1080、16:9、24 fps，依要求維持標題與主體安全區。
- **跨媒介**：工具不支援某關鍵要求時，先誠實告知並在**已授權的替代媒介**中工作；不能暗中偷換交付物。

## 只做文件、修錯字與程式修補時的比例原則

不強迫所有文字／README PR 渲染影片。對非視覺改動，G2/G3 改為**最小有意義測試**（例如文件連結、規格與引用、單元測試／介面驗證）。但若 PR 聲稱已改善**視覺／動畫／實際體驗**，就必須附符合該主張的 B/C/D 層實測證據，或清楚標記尚未測試。

## 每次交付必填的簡短報告

```text
交付需求 / 不可替代的格式：
參考品質門檻：
當前階段：RESEARCH | SPIKE | PREVIEW | CANDIDATE | FINAL-APPROVED
最小樣片：有（連結）/ 無（原因）
A 結構：PASS | FAIL | NOT RUN（證據）
B 靜態：PASS | FAIL | NOT RUN（證據）
C 原生實播 / 互動：PASS | FAIL | BLOCKED | NOT RUN（播放器 / 證據）
D 桌面 / 手機：PASS | FAIL | BLOCKED | NOT RUN
E 內容與授權：PASS | FAIL | BLOCKED | NOT RUN
跟參考的主要落差：
發現的缺陷及重新製作決策：
下一步與負責範圍：
PR / CI：連結、狀態；不要當成品質總結
使用者驗收：未核准 | 已核准
```

**例子（Anatomy Morph）**：如果 13 段 Morph XML 都存在，但沒有 Microsoft PowerPoint 實播 → `A: PASS`、`C: BLOCKED`，最終狀態僅可為 `CANDIDATE`，絕不寫成 `FINAL-APPROVED`。
