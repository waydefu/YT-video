# PowerPoint 無縫轉場手法目錄（研究）：依內容類型選用，每頁可以不同

> 版本 2026-11-07｜狀態：**RESEARCH**。本文件是研究與提案，**不是任何成品通過驗收的證據**。微軟官方頁面已逐頁讀過（A 級）；社群教學多數只看到搜尋摘要（B 級）；匯出影片、效能等只有零散使用者回報（C 級）。**沒有 Microsoft PowerPoint 可實播，所有「做得到／好看」的判斷都是 B 層（靜態＋幾何代理）或文件上的說法，C/D 層 NOT RUN。**

## 0. 為什麼寫這份

使用者的回饋（2026-11-07）：參考影片靠「畫框」放前頁／下頁很自然，因為**內容是圖片**；本專案的 AI 訂閱簡報是表格與圖表，畫框只是裝飾。並明確說：**可以找多種手法，每頁都可以不一樣，不必整份簡報用同一種轉場。**

所以這份文件的做法是：先查有哪些手法與限制，再**依內容類型**挑選，最後給「逐頁分配」的提案（§5）。

## 2. 已確認的事實（A 級，含對本專案的影響）

| 事實（微軟官方頁面） | 對本專案的影響 |
| --- | --- |
| **圖表不會 Morph，只會交叉淡入**（"charts … don't morph, they cross-fade"） | 長條圖／數字比較**必須用形狀（矩形、文字）自己畫**，才能做資料變形。（先前有搜尋摘要誤稱圖表支援，**以官方頁面為準**。） |
| 同類型、**同名且以 `!!` 開頭**的物件在相鄰兩頁會被配對；`!!` 物件不會與非 `!!` 物件配對；一頁內名稱需唯一 | 本專案 `pptx_world.py` 已用 `!!Pxx_name` 命名；共享元素手法的核心 |
| 任兩個**同類型**物件可被強制 Morph（表格↔表格、SmartArt↔SmartArt、圖片↔圖片） | 可行但我沒測；本專案目前只用形狀、文字、圖片 |
| **有多個孔洞的形狀無法做幾何 Morph**；有編輯點的形狀前後頁需「大致相同」的編輯點數與同方向 | 「字母變形狀」類特效（O、A、B 有孔）有風險，見 T10 |
| Effect Options：**Objects／Words／Characters**；Words 強調字詞的新增、移除、移動；Characters 用於易位構詞 | 標題換字可用 Words；本專案 `pptx_morph_patch.py` 目前**固定寫 `byObject`**，要用得先擴充 |
| 文字顏色／格式變化會被平滑動畫 | 重點字上色可用 |
| **Zoom（插入 > 縮放）有三種**：摘要縮放（Summary Zoom）、投影片縮放（Slide Zoom）、章節縮放（Section Zoom）；有「返回縮放」（Return to Zoom）與「縮放轉場」（Zoom Transition，可調長度）選項 | 這是 PowerPoint **原生的「地圖／中樞」功能**，見 T9 |
| Zoom 需求：Microsoft 365（1607 以上）、2019、2021、2024 可建立並播放；**2016 只當超連結播放（無縮放動畫）；網頁版與 Teams PowerPoint Live 無**；Android／iOS／Mobile 只能播放 | 觀眾環境受限；若要從 PowerPoint 匯出影片，用桌面版即可 |
| Morph 版本：Microsoft 365、2019 起；2016 的 16.0.4888 僅**放映**時可播，不能在一般檢視建立 | 同上 |
| 官方頁面**沒有提到**：匯出影片是否保留 Morph 或 Zoom、3D 模型與影片是否 Morph、Zoom 動畫曲線與時長數值 | 這些都列為**未驗證**（§6） |

## 3. 手法目錄

「本專案現況」：**已實作**＝在 repo 中有程式與測試；**樣片**＝在尚未合併的 PR #12 中；**提案**＝未實作。

| 編號 | 手法 | 內容類型 | 做法（Morph 為主） | 本專案現況 | 風險／備註 |
| --- | --- | --- | --- | --- | --- |
| T1 | **平移**（相鄰頁並排，鏡頭橫移／下移） | 任何並列頁、時間序列 | 面板並排，縮放不變，只移動 | 已實作（`pptx_world.py` 的 `pan_right`／`pan_down`） | 最穩；單用會平淡 |
| T2 | **鑽進視窗／拉遠揭露**（畫框） | **圖片**、圖解、示意圖 | 下一頁縮在視窗內；拉遠時揭露它掛在更大場景的畫框 | 已實作（見 PPTX-SEAMLESS-EXPLAINER） | 對表格圖表是裝飾、縮圖看不清；圖片頁才自然 |
| T3 | **地圖巡覽（Board）**：中樞頁放多張卡片視窗→放大進第一張→在相鄰卡片間平移→縮回中樞 | 多個並列模組（七個平台、五個章節） | `nest`／`zoom_out`：子頁放在中樞視窗內，回程重畫同名物件 | **樣片**（PR #12 的 7 頁樣片，B 層通過） | 縮放約 3.7×，略高於經驗值；一張地圖 5–6 張卡片為宜 |
| T4 | **共享元素變形**：同一批形狀移動／縮放／換色，變成下一種圖 | 表格→長條、數字比較、價格→成本 | 以矩形與文字畫出長條，兩頁用相同 `!!` 名稱；寬度、位置、顏色由 Morph 補間 | **提案**（做法簡單，PR #12 的 20 頁稿尚未用） | 微軟：**原生圖表不 Morph**，所以必須用形狀畫；Gramener 教學同做法（B） |
| T5 | **導讀高亮**：一條半透明高亮條（或框）在表格列／清單項間滑動，旁欄文字隨之換 | 表格、檢查清單、規則列表 | 表格不動（同名物件），只有高亮條與旁欄說明換位置／內容 | **提案** | 一頁拆成多頁，頁數增加；每步停留要配旁白 |
| T6 | **卡片輪播**：整排卡片左移一格，新卡從右側進入，標題與頁首不動 | 情境選擇、方案比較、多選項 | 卡片物件同名，位置平移；離場卡片淡出 | **提案** | 與 T1 不同在於標題固定、只有內容流動 |
| T7 | **下鑽／手風琴**：某列或某長條放大成該項的詳細內容 | 列表→詳細說明 | 該列物件放大並淡入說明；其餘列變暗或收起 | **提案** | 要設計放大後的版面；縮放比需控制 |
| T8 | **文字變形（Words／Characters）**：標題換字，相同字詞滑動重排 | 章節標題、結論句 | 把 Effect Option 設為 Words 或 Characters | **提案**；需擴充 `pptx_morph_patch.py`（目前固定 `byObject`） | 第三方轉換器可能降級成淡入（B）；先在標題用，不用於密集正文 |
| T9 | **PowerPoint 原生 Zoom（Slide／Section／Summary Zoom）**：中樞頁放縮圖，點進去放大、播完自動返回中樞 | 導覽、章節總覽 | 插入 > 縮放；勾選 Return to Zoom 與 Zoom Transition | **未做**：要產生原生 Zoom 物件需自行寫其 OOXML，而我**沒有 PowerPoint 做出的範本檔可對照**，不能保證格式正確 | 官方列出 2016、網頁版不支援（A）；影片匯出是否保留未驗證。T3 是我可控的等價做法，兩者擇一或並用 |
| T10 | **鑽進字母／文字遮罩揭露**：巨大字母（或把文字合併為形狀）鑽進去，內部是下一頁 | **封面／章節開場**，單一標題 | 文字轉形狀（Merge Shapes：Fragment／Intersect），形狀放大 | **未做、不建議用於資料頁** | 多孔字母（O、A、B）無法幾何 Morph（A）；社群說法為 B；需字型輪廓與授權 |
| T11 | **圖片裁切縮放／平移（Ken Burns）**：大圖在頁面外延伸，複製頁後放大或移動 | 官方圖片、照片、海報 | 圖片裁切框移動，縮放 | 已用於圖片類（Anatomy 13 頁，以畫框法呈現） | 需高解析來源圖；微軟官方 Tips 頁亦有縮放／捲動圖片的做法（A） |
| T12 | **3D 模型旋轉 Morph** | 實體物件、產品 | 插入 3D 模型，複製頁後旋轉 | **未做** | 微軟頁面沒有提到 3D；問答指出**陰影會讓 Morph 失效**（B）；需有授權的 GLB 素材；與 AI 訂閱簡報無關 |
| T13 | **環境循環動態**（呼吸、漂浮、旋轉） | 圖片或圖解的背景生命感 | 見 PPTX-LIVE-MOTION | 已實作 | 不是 Live2D；資料頁不宜 |

## 4. 依內容類型選用

| 內容 | 優先考慮 | 避免 |
| --- | --- | --- |
| **單一標題／封面／章節開場** | T8 文字變形；圖片封面可 T11；巨型字母 T10 只用於不含孔洞的簡單字形 | 在資料頁用 T10 |
| **表格** | T5 導讀高亮（逐列讀）；T4（表格→長條）；T7 下鑽到某列詳細說明 | 把表格縮成畫框縮圖（T2） |
| **數字比較／長條** | T4 共享元素（用形狀畫，不用原生圖表）；數值變化時長條寬度補間 | 用原生圖表期待變形（只會淡入） |
| **多個並列模組（七平台、五章節）** | T3 地圖巡覽；T6 卡片輪播；T9 原生 Zoom（環境允許時） | 同一手法連用超過一輪（會單調） |
| **清單／規則／檢查表** | T5 高亮；T1 平移 | 把整頁當畫框 |
| **圖片／官方圖／海報** | T11 裁切縮放；T2 畫框（圖片才自然）；T13 環境動態 | 拉高到 >3.5× 的縮放而無拆步 |
| **結論／回顧** | T3 的縮回中樞（`zoom_out`）、T8 結論句變形 | 新增大量新物件 |

**混用規則**（使用者已確認可以每頁不同）：
1. 一個轉場只用一種手法；相鄰轉場盡量換手法，避免連續三次相同。
2. 相機位移類（T1、T2、T3）與「相機靜止、物件變形」類（T4–T8）可以混用。相機靜止的做法在 `pptx_world.py` 中可用 `zoom_out(to=前一頁)`（回到同一面板並重畫）：同名物件延續，其他物件淡入淡出。**`zoom_out` 目前只在尚未合併的 PR #12，main 上還沒有。**
3. 每步縮放比約 3.5× 以內（經驗值，需實播驗證）；單頁物件數量要控制（效能回報為 C 級，只能保守處理）。
4. 資料頁一律不用 T10、T12。
5. 每個轉場在 §5 表中**先記錄手法與理由**，驗證器與代理幀檢查過再進成品。

## 6. 已知風險與未驗證項（必讀）

1. **PowerPoint 實播未執行（C 層 NOT RUN）**：緩動、字級縮放、文字處理、Zoom 轉場表現都未見實物。代理幀只能**否決**設計。
2. **匯出影片是否保留 Morph／Zoom 未驗證**：微軟三頁都沒提；第三方說法不一（有的說保留、有的說複雜效果可能失真或掉格；C 級）。成品要上 YouTube 前，必須在 Windows 桌面版實際匯出並逐段檢查。備案是螢幕錄製放映（另一條製作流程，需要使用者同意）。
3. **原生 Zoom（T9）無法由我產生**：需要真實 PowerPoint 檔作為 OOXML 範本；在此之前只能用 T3 的等價做法，或請使用者在 PowerPoint 手動插入。
4. **版本與平台**：Morph 需 Microsoft 365／2019 以上；Zoom 同樣，且網頁版不支援（A）。觀眾端若是影片則無此限制。
5. **效能**：一頁數十到上百物件在低階電腦放映可能不順（C 級回報）；Morph 的相同物件配對錯誤也會造成亂跳，需靠唯一 `!!` 名稱避免（A）。
6. **字型**：簡報指定的字型必須在播放電腦上已安裝（不隨附）。
7. **我沒有**研究 Keynote「神奇移動」、Canva、Figma 等其他工具；專案契約是原生 `.pptx`，所以本文件只涵蓋 PowerPoint。
8. **本文件的「手法難易」多為我的判斷**：T4–T8 我預期容易以現有 `pptx_world.py` 建構，但**尚未實作與驗證**；到實作時才能確認。
